# Мирас Ринатулы — инструкция по backend

Эта инструкция описывает зону ответственности второго участника: корректность подбора и API-контракт, которым пользуется frontend.

## 1. Запуск

Из корня проекта:

```bash
python3 app.py --port 8001
```

Откройте `http://127.0.0.1:8001`. Порт 8001 удобен, если на 8000 уже запущен другой экземпляр. Остановка — `Ctrl+C`.

## 2. Основные функции

- загрузка каталога из `data/contractors.csv`;
- `GET /api/meta` — варианты полей, статистика и готовые сценарии;
- `POST /api/recommend` — проверка запроса, фильтрация, ранжирование и объяснения;
- обработчики HTTP-ошибок и JSON-ответов.

## 3. Путь одного запроса

1. Проверяются город, дата, формат, категория, бюджет и дополнительные поля.
2. Выбирается пул точного города и категории.
3. Отбрасываются занятые, слишком дорогие и несовместимые по формату, языку или часам профили.
4. Оставшиеся ранжируются по совпадению пожеланий, затем по цене и ID.
5. Первые три получают фактическое объяснение и цитату.
6. Ответ содержит статус и аудит исключений.

## 4. Граничные случаи

- `no_category` означает, что в выбранном городе нет такой категории.
- `no_match` означает, что категория есть, но ни один профиль не проходит условия.
- `max_hours=null` не исключает профиль по длительности.
- Один профиль может иметь несколько причин исключения, поэтому суммы счётчиков причин могут пересекаться.
- Один и тот же запрос и каталог должны сохранять порядок карточек.

## 5. Координация

**Темирлан:** сохранять имена endpoint и JSON-полей `status`, `cards`, `message`, `rejected`, `exclusion_counts`, `elapsed_ms`.

**Айназ:** не менять схему профилей и уникальные ID без аудита. После изменений запускать `python3 tools/audit_data.py --include-synthetic --markdown`.

## 6. Проверка

```bash
python3 -m unittest discover -s tests -v
```

Ожидаемый результат — 10 тестов со статусом `OK`. Backend использует объяснимый лексический baseline и не запускает LLM во время работы приложения.
