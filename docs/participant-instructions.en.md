# HackAlem AI Participant Instructions — English Translation

Source: the organizer's participant instructions, preserved in `participant-instructions.pdf` and `participant-instructions.txt`. This translation is provided for the team; the original remains authoritative.

1. Activate access to Codex, the OpenAI API and NVIDIA using the separate activation instructions. Do not publish API keys on GitHub.
2. Choose one challenge. You do not need to solve every challenge in a track.
3. Read the challenge requirements and evaluation criteria.
4. Discuss implementation with the team and assign roles and tasks.
5. Choose a development workflow:
   - In the Codex application, connect your GitHub account, provide access to the platform-created team repository folder, and issue tasks through prompts.
   - In Visual Studio Code, install the Codex extension, sign in, open the team repository, develop the solution and push code to GitHub.
   - Other development methods are allowed. The important requirements are using an AI agent and placing the final code in the team repository assigned by the hackathon platform.
6. Within five hours, implement the challenge's mandatory requirements and verify the main scenario from input to result.
7. Prepare the README. Describe what the project does, implemented features, technologies and architecture, installation and startup, a verification example, data and external services, known limitations, and a deployment link if one exists.
8. You may use the organizers' README prompt through Codex.
9. Push the latest project version to the team GitHub repository.
10. Open the tracks page, select your challenge and choose Submit Solution. Enter the project name and description. The solution can be updated until the hackathon deadline.

## Organizer README Prompt

Analyze the current project and create a complete README.md in Russian. It must be understandable to hackathon judges and contain:

1. Project name.
2. A short description of the problem and intended audience.
3. Implemented features and capabilities.
4. The main user journey from input to result.
5. Languages, frameworks, libraries, AI models, APIs and external services.
6. Main architectural components and how they interact.
7. Step-by-step installation and startup commands.
8. A verification scenario judges can reproduce.
9. Data sources and integrations.
10. Unimplemented features and current limitations.
11. A deployment link, if one exists.

Use only facts supported by the repository. Do not invent features, technologies or results. Format the README clearly in Markdown.

## Team Implementation Note

The project owner requested English developer documentation while retaining the Russian website. The main README is English, and `docs/README.ru.md` preserves the Russian version for the organizer requirement. No account activation or platform submission is performed by translating this document.
